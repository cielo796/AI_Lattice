# AI Lattice 実行画面 改善案 実装メモ

対象画面：アプリ実行画面（レコード一覧、`/apps/:appId` 相当）
デザイン：[AI Lattice 実行画面 改善案（キャンバス）](https://claude.ai/code/artifact/7cf238db-85e1-4a9c-b02e-cda10277d847)
準拠するデザインシステム：AI Lattice（ネイビーテーマ）

> コード例は React + TypeScript と CSS 変数で書いています。既存のフロントエンドの構成（CSS Modules、Tailwind など）に合わせて置き換えてください。

---

## 1. 現状の課題

| # | 課題 | 影響 |
|---|------|------|
| 1 | サイドバーに17項目が同じ扱いで並び、利用者向け・アプリの設計・テナント管理が混在している | どこから操作すればいいか分からない |
| 2 | アプリの選択が小さなドロップダウンだけで、アプリ名が見出しになっていない | 今どのアプリを見ているか分からない |
| 3 | レコードが縦長のカードで並び、「説明はありません」が繰り返される | 一覧性が低く、3件で画面が埋まる |
| 4 | 状態ラベルが右端に離れている | 行と状態の対応を目で追いにくい |
| 5 | コーラルの強調ボタンが2つある（作成／新規レコード） | 主な操作が分からない。コーラルはロゴ専用のルールに反する |
| 6 | AIアシスタントが一覧の下にある | 件数が増えると見えなくなる |

## 2. 3案に共通する変更

### 2.1 ナビゲーションの再編

現在のメニュー17項目を、次の4つのグループに分けます。

| グループ | 含める項目（現在の名前） | 表示する人 |
|----------|--------------------------|------------|
| ワークスペース | ダッシュボード → **ホーム**、承認、通知 | 全員 |
| アプリ | アプリ、アプリトップ → **アプリ一覧／最近使ったアプリ** | 全員 |
| アプリの設計（アプリ単位） | テーブル、ワークフロー、権限設計、アプリ設定 | アプリの編集権限がある人 |
| 管理（テナント単位） | テナント、テナント設定、ユーザー管理、ロール管理、アプリ承認、Prompt Template、OpenAI 設定 | テナント管理者 |
| アカウント | プロフィール | 全員（アバターのメニューへ移動） |

- 「管理」はサイドバーに1項目だけ置き、遷移先の管理画面に左タブで7項目を並べます。
- 「アプリの設計」は、アプリを開いているときだけ出します（案B）か、「アプリを編集」ボタン／「編集モード」の先に置きます（案A・C）。

### 2.2 アプリヘッダー

- アプリ名を `page-title`（26px / 700）で表示します。1画面に1つだけです。
- 補足としてテーブルのコードを等幅で出します（例：`inventory_item`）。
- 主要ボタン（紺の塗り）は **「レコードを追加」1つだけ** にします。「新規レコード」から文言を変えます（動詞＋目的語）。
- コーラル（`--al-logo`）はロゴ以外に使いません。

### 2.3 一覧はカードから表へ

| 列 | 内容 | 備考 |
|----|------|------|
| レコード | タイトル（`body-strong`、リンク）＋ID（`code`、`ink-subtle`） | 2段で表示 |
| 品目名 | 文字列 | |
| 在庫数 | 数値 | 右寄せ、`tabular-nums`、3桁区切り |
| 保管場所 | 文字列 | `ink-muted` |
| 状態 | 状態バッジ | 次の表を参照 |
| 更新 | 相対時刻（例：51日前） | |

- 「説明」が空のときは一覧に出しません。詳細画面では「未入力」を `ink-subtle` で表示します。
- 表は横スクロールできる箱（`overflow-x: auto`）に入れ、最小幅を指定します。
- 表の下に件数（「3件中 1–3件を表示」）を出します。

### 2.4 状態バッジの対応

| 状態 | 種類 | 面 | 文字 |
|------|------|----|------|
| 通常 | neutral | `--al-surface-sunken` | `--al-ink-muted` |
| 要確認 | warning | `--al-warning-tint` | `--al-warning` |
| 完了 | success | `--al-success-tint` | `--al-success` |

色だけで区別せず、必ず文言と一緒に出します。

### 2.5 AIアシスタント

- 一覧の下には置きません。案ごとの置き場所は次のとおりです。
  - 案A：右パネル（開閉できる）
  - 案B：レコード詳細パネルの中
  - 案C：画面下の質問バー
- レコードを選んでいないときは、ボタンを無効にして理由を `caption` で書きます（「レコードを1件選ぶと使えます」）。
- AIが作った内容には必ず「AI提案」ラベルを付けます。

### 5.2 寸法と振る舞い

| 要素 | 仕様 |
|------|------|
| 上部バー | 白の面、高さ64px前後。アプリ切り替え、全体検索、全体メニュー、通知、管理、アバター |
| 全体検索 | Ctrl K（Mac は ⌘K）で開く。レコード・アプリの検索とAIへの質問を兼ねる |
| 編集モード | `role="switch"`。オンにすると、テーブル／ワークフロー／権限設計／アプリ設定のタブがビュータブの右に出る |
| ビュー切り替え | セグメント型（`--al-border` の地に、選択中は白＋薄い影） |
| 状態フィルター | チップ型のボタン（`aria-pressed`）。件数を等幅数字で並べる |
| 表 | 作業エリアの全幅。行末に「…」メニュー（編集・複製・削除はここに入れる。削除を行に直接並べない） |
| AI質問バー | `--al-shadow-pop` 付きで画面下に置く。よく使う操作は既存の「AIで要約」「AIで提案」に対応させる |
| レスポンシブ | 768px未満でグローバルメニューをハンバーガーに、状態フィルターを横スクロールに |

## 6. 案の比べ方

| 観点 | 案A | 案B | 案C |
|------|-----|-----|-----|

### 8.2 状態バッジ

```tsx
type StatusKind = "neutral" | "warning" | "success" | "danger";

const STATUS_KIND: Record<string, StatusKind> = {
  通常: "neutral",
  要確認: "warning",
  完了: "success",
};

export function StatusBadge({ label }: { label: string }) {
  const kind = STATUS_KIND[label] ?? "neutral";
  return <span className={`al-badge al-badge--${kind}`}>{label}</span>;
```

## 9. アクセシビリティ

- サイドバーは `<nav aria-label="メインメニュー">`、ビューの切り替えは `<nav aria-label="ビュー">` にする。
- 選択中のメニュー・タブは `aria-current="page"`、選択中の行は `aria-current="true"` にする。
- アイコンだけのボタン（更新・…・閉じる・通知・管理）には `aria-label` を付ける。アイコンの SVG は `aria-hidden="true"`。
- AIパネルの開閉ボタンと状態フィルターのチップは `aria-pressed`、編集モードは `role="switch"` と `aria-checked` にする。
- 検索欄にはラベル（`aria-label` か、画面上は隠した `<label>`）を付ける。
- タップできる領域は 40〜44px 以上にする。
- フォーカスは `--al-focus` の 2px 実線＋2px オフセットで、全ての面で見えるようにする。
- 本文は14px。12px を使うのは `label` と `caption` だけにする。

## 10. 実装の進め方（案Aを選んだ場合の例）

1. CSS 変数（7章）を全体に入れ、既存のコーラル（ボタン・アクティブ状態）を紺に置き換える
