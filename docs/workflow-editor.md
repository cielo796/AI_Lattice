# ワークフローの編集と検証

更新: 2026-09-30

## 操作

アプリの「ワークフロー」から編集します。閲覧には `workflow:read`、新規作成・保存・有効化・削除には `workflow:manage` が必要です。管理権限がない場合は設定欄と変更操作が無効になります。

1. 「空テンプレート」または「アプリ承認テンプレート」を選び、新規作成します。既存の編集中グラフをコピーする操作ではありません。
2. ワークフロー名、トリガー種別、保存する状態を設定します。承認テンプレートはアプリ承認設定を参照します。
3. ツールバーから7種のノードを追加します。ドラッグまたは座標欄で移動できます。開始トリガー以外は複製できます。削除時には関連する接続も削除します。
4. ノードのポートをドラッグして接続するか、右側の「接続を追加」で接続元・接続先・分岐を指定します。ノード一覧・接続一覧からも対象を選択できます。
5. 接続を選んで分岐・ラベルを編集、または削除します。条件は `yes` / `no`、承認は `approved` / `rejected` / `returned` が基本の分岐です。条件のカスタムラベルも利用できます。反対側の予約ラベルは指定できません。
6. 「有効化前の検証」でエラーを確認し、保存します。「保存」は選択中の状態を維持します。有効なワークフローの不完全な変更を保存したい場合は、保存する状態を下書きへ変更してください。

パン・選択モード、拡大・縮小・全体表示は利用できます。未保存の変更は表示され、別ワークフローへの切替や新規作成時に破棄を確認します。通常のページ再読み込み・終了にはブラウザーの確認を使います。アプリ内の全ナビゲーションを阻止する仕組みはまだありません。

## 設定できる内容

| ノード | 設定 |
| --- | --- |
| トリガー | ワークフローと同期するトリガー種別、アプリ内の対象テーブル |
| 条件 | フィールド・演算子・比較値、一致/不一致ラベル |
| 承認 | アプリ承認設定の参照、明示的な一時上書きの承認者・依頼内容・4種のステータス |
| 通知 | 実行者/ロール/明示ユーザー、タイトル・本文・重複キー・失敗ポリシー |
| ステータス更新 | 更新先ステータス・失敗ポリシー |
| API呼び出し | URL・メソッド・ヘッダーJSON・本文JSONテンプレート・100〜30000msのタイムアウト・失敗ポリシー |
| AIアクション | 要約/次アクション/返信案、任意モデル、有効なPrompt Template、コメント/文字列フィールドへの出力・失敗ポリシー |

テンプレート変数は `appCode`、`tableCode`、`tableName`、`recordId`、`recordTitle` です。API本文はJSONとして解析してから文字列値を置換するため、件名に引用符が含まれてもJSONを壊しません。URLそのものはテンプレートではありません。ヘッダーに認証情報を保存しないでください。Authorization・Cookie・Host・Idempotency-Keyなどの予約ヘッダーは拒否します。秘密情報参照によるAPI認証は未実装です。

API送信先はサーバー環境変数 `WORKFLOW_API_ALLOWED_ORIGINS` で許可します。未設定・未許可の送信先は有効化時にも拒否され、実行時に再確認します。リダイレクトには追従しません。運用中に許可リストが変更された場合は、ノードの失敗ポリシーに従います。

AIの有効なPrompt Templateにモデルが設定されている場合は、そのモデルが優先されます。実際のモデル名を結果・監査に記録します。明示的に選択したPrompt Templateが消えた、無効になった、または取得できない場合は、別の指示へ黙って切り替えず失敗します。AI実行者には `ai:execute` も必要です。外部モデルへの通信と費用が発生します。

## 保存・有効化の検証

下書きでも重複ID、存在しない接続先、循環、空のノード名を拒否します。未接続ノードや未完成の設定は下書きとして保持できます。

有効化時はクライアントとサーバーで種類別configを検証し、サーバーが現在のDBから参照先を再取得します。対象テーブル、比較フィールド、同一組織の有効ユーザー、アプリ承認設定、AI出力先フィールド、有効なPrompt Template、API許可オリジンを確認します。対象テーブルを限定しない場合、条件フィールドとAI出力先はアプリ内の全対象テーブルに存在する必要があります。実行時のRBACは引き続き別途適用します。

`GET /api/apps/:appId/workflows/editor-context` は編集用のメタデータだけを返します。別組織のアプリや権限不足からは取得できません。

- `workflow-config.test.ts` / `workflow-editor.test.ts` / `editor-context.test.ts`: config・参照先検証、グラフ操作、メタデータの組織・権限境界を検証します。
