# アプリ作成画面の実装・確認記録

対象: `/apps/new/ai`。添付 `ai-lattice-app-creation/SPEC.md` に沿った改修。

この文書は初回のアプリ作成実装の記録です。その後の全画面3テーマ・表示設定・ホーム刷新は `docs/design-refresh.md` を参照してください。現在の配色はグローバルな `tokens.css` を使用します。

添付の画面構成・操作へさらに近づけ、現在の配色を維持した最新の改修と検証結果は [参照実装への再調整](app-creation-reference-alignment.md) を参照してください。

## 既存実装の調査結果

| 確認事項 | 結果・実装方針 |
| --- | --- |
| フロントエンド | Next.js 16.2.3 / React 19.2.4。Reactのクライアント状態を使用。既存のフォーム用DnDライブラリはなく、Pointer Eventsを使用。 |
| フォームの幅 | `AppForm.layoutJson.fields[].width` の文字列 `full` / `half`。ピクセルや割合ではない。行順と空き枠を維持する `rowIndex` も保存し、ランタイムで反映。マッピングのコメントは `blueprint-layout.ts`。 |
| 初期ビュー | 既存判定を `blueprint-views.ts` に移し、表示と保存が同じ関数を使用。数値だけでチャートを追加する参照デモの仮ルールは採用しない。 |
| モデル | 有効なPrompt Templateのモデル指定、次にテナント既定モデル。モデルゲートウェイの共通解決関数をGET APIと生成が使用。クライアントで推測しない。APIキー不足時の既存エラー優先順位も維持。 |
| 生成API | 一括JSON応答。段階表示は経過時間に基づく目安と明記。AbortControllerをAPIとモデル呼び出しへ渡し、遅れて届いた応答を反映しない。 |

## 実装内容

- 3ステップ、1000文字の説明欄・文字数・入力ヒント、挿入のみの5つの入力例、置き換え確認。
- 使用モデルと決定元を読み取り専用表示。変更は管理画面。
- 7部品、AI追加候補、フォーム／表の編集、ドラッグ・タッチ・キーボード、全幅／2列、空き枠、複製・削除。
- 自動／手動コード、形式・重複エラー、選択肢のタグ入力・重複通知、追加時のフォーカス。
- AIの理由・配置・おすすめを出力スキーマに追加。有効な旧Prompt Templateはモデルを維持し、その指示に新要件を補足して新しい出力スキーマを使用する。保存済みテンプレートを無断で書き換えない。
- AI調整は未保存の設計案を入力に送り、追加／変更／削除を確認してから適用／破棄。再生成は編集の維持／全体の作り直しを選択。
- 手動コード・項目ID・編集履歴は部分調整後も維持し、次の再生成で引き継ぐ。
- 1アプリ・1テーブル、1〜10フィールド、下書き、サンプル3件、既存の初期ビュー判定、保存後の遷移を維持。
- 保存リクエストでは選択肢をカンマ区切りに結合。サーバーで分割し、既存の `AppField.settingsJson.options` 配列として保存するため、既存アプリとの互換性を維持。
- 新しいDBテーブルやマイグレーションは不要。既存のフォーム設定に配置を保存。

## トークン対応

画面専用CSSに添付tokens.cssと同じライト／ダークの値を定義。`data-theme="dark"` を継承する。既存の全ページ配色は変更せず、作成画面がある場合のみ共通サイドバー・ガイドの色も対応づける。

| 既存の用途 | 添付トークン |
| --- | --- |
| ページ／サイドバーの背景 | `surface-page` |
| カード・入力の面 | `surface-card` |
| 無効・読み取り専用・フォームの地 | `surface-sunken` |
| 本文／補足／プレースホルダー | `ink` / `ink-muted` / `ink-subtle` |
| 入力の枠／装飾枠 | `border-control` / `border` |
| 主ボタン・文字 | `brand-strong` / `on-brand` |
| 選択・AI提案 | `brand-ink` / `brand-tint` |
| フォーカス | `focus` |
| 追加／変更／削除 | `success` / `warning` / `danger` と対応する `*-tint` |

| 7 | Alt＋矢印、読み上げ、Esc | E2EでAlt＋↓とaria-live、Escで件数が不変。単体テストで左右の交換と隣行への合流。 |

| 12 | layout欠落・不正を許容 | 欠落・重複・不明コード・3列・漏れを単体テスト。旧形式の生成結果をE2Eで全幅表示。 |

## 検証の範囲

### 実行結果（2026-10-06）

- `npm run quality`: 成功。文字化けチェック、ESLint、単体テスト420件、TypeScriptの型チェックを実行。既存のDB統合テスト32件はスキップ。既存の `src/app/layout.tsx` のフォント警告1件のみで、新規エラーはない。
- 専用E2E: 4件成功。入力・中断・ドラッグ・タッチ・キーボード・空き枠・上限・タグ・差分・編集維持の再生成・保存・モバイル・両テーマを確認。
- 本番ビルド: 無関係なWebhook変更を含めない検証用コピーで、Next.jsの標準Turbopackビルドが成功。コピー先の `node_modules` はリンクなので、検証用コピーだけ `turbopack.root` をリンク先と共通の親ディレクトリに指定。リポジトリの設定や依存パッケージは変更しない。Webpackビルドは既存のGoogle Fontsローダーで失敗したため、標準ビルドとは区別する。
- スクリーンショット: `app/test-results/creation-describe-light.png`、`creation-review-light.png`、`creation-review-dark.png`、`creation-mobile.png` を確認。モバイルではサイドバーの余白遷移完了を待ち、横スクロールがないことも検査。
- 起動中の `http://127.0.0.1:3000` のローカル実行用コピーへ今回のソースを反映。`/login` のHTTP 200を確認。

初回の自動検証ではAI応答をモックし、実モデルには課金リクエストを送っていない。認証・下書き作成・テーブル・フィールド・フォーム・ビュー・サンプルの保存は、Supabaseではなく隔離したローカルPostgreSQLで実行。自動検証で作成したテストアプリは削除する。

### Browser-useによる実環境検証（2026-10-06）

ユーザーの追加依頼に基づき、Codex内ブラウザから `http://127.0.0.1:3000` を実操作。AI応答や保存APIはモックしていない。

- デモアカウントのログイン、入力例の挿入のみ、置き換え確認のキャンセル、1000文字上限、Ctrl＋Enterでの生成を確認。画面が示す既定モデル `gpt-6-luna` で実際の生成が成功。
- 長文部品をフォーム末尾へドラッグし、追加直後の表示名フォーカスを確認。数値部品を右端へドラッグして2列化し、Alt＋↓で単独行へ移動した後の空き枠も確認。
- 名前の即時反映、手動コードの形式エラーと保存不可、正常コードへの復帰、選択肢の読点分割・重複通知、複製・10項目上限、表形式での編集を確認。テスト用の複製は未保存の段階で取り消した。
- 実AIの部分調整で「入荷日：任意 → 必須」だけが差分に出ることを確認し、適用。手動コード・選択肢・配置は維持。再生成の確認画面には編集維持／全体作り直しの両方が表示され、今回は閉じて追加生成しなかった。
- 390px幅で設定ドロワー、カード選択、Escで閉じる操作を確認。横はみ出しはない。ブラウザの一時的な画面サイズ指定は検証後に解除。実機iPadは引き続き未検証。
- 接続済みSupabaseの `ai_lattice` スキーマへ検証用アプリ「Browser-use検証・倉庫在庫管理」を下書き保存。1テーブル、9項目、1フォーム、5ビュー、サンプル3件を画面で確認。公開・既存データの削除・DB権限変更は行わず、検証用下書き1件を残した。
- 保存済みフォームを編集表示で読み取り、7項目の半幅と2項目の全幅、並び順、必須5項目を確認。実ランタイムでも長文の半幅・右側の空き枠・後続の全幅を確認。空欄の新規レコードは必須検証で拒否され、保存せず閉じた。
- 一覧・カンバン・カレンダー・チャート・集計を実表示。通常／要確認／完了に各1件、カレンダーに3件、在庫数の合計105,340・平均35,113.3を確認。ブラウザのコンソールエラーは0件。
- 証跡は `app/test-results/browser-use-creation-review.jpg`、`browser-use-creation-mobile.jpg`、`browser-use-created-app.jpg` に保存。これらのスクリーンショットはGit管理対象外。

### 既存画面の確認事項（今回の変更対象外）
