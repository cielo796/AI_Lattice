# テーブル設計画面のドラッグ式フォーム配置

対象: `/apps/[appId]/tables`。実装・確認日: 2026-10-06。

## 使い方

1. テーブルを開き、上部の「フォーム配置を編集」を押す。未編集中なら先頭の保存済みフォームを開き、フォームがなければ新規作成する。
2. カードを上下にドラッグして順番を変える。1項目のカードの左右端へ置くと2列になる。ペアから項目を抜くと空き枠を維持し、そこへ別の項目を置ける。
3. カードのボタン、または選択中の項目設定で全幅／2列を切り替える。非表示の項目はパレットからドラッグ、クリック、Enter／Spaceで戻せる。
4. 項目設定でフォームへの表示・フォーム内の必須・入力時の補足を変更する。テーブルで必須の項目は非表示や必須解除ができない。
5. 「フォームを更新」または「フォームを作成」で保存する。未保存の配置は実行画面へ反映しない。新しいテーブル項目の追加・型変更には既存の「新規フィールド」「編集」を使用する。

カードにフォーカスした状態でAlt＋矢印による移動・左右入れ替え、Deleteによる非表示、Escによるドラッグ取消が可能。読み上げ通知を付け、連続するキーボード移動でもカードのフォーカスを維持する。タッチはPointer Eventsで対応する。

## 保存と互換性

- 変更対象はフォームの項目順・幅・表示・フォーム内の必須・補足。テーブルの `sortOrder`、フィールドの型・一意制約・参照設定、既存レコードは変更しない。非表示は項目削除ではない。
- 既存12型をフォーム上で表示でき、AI作成の10項目制限は手動テーブルのフォームには適用しない。
- 保存先は既存の `AppForm.layoutJson.fields`。幅は既存の `full` / `half`、行は0始まりの `rowIndex`。新しいスキーマやマイグレーションは不要。
- テーブル設計の読み込み・保存と、フォームAPIの正規化で `rowIndex` が落ちていたため、両方で有効な行位置を維持するよう修正した。空き枠も保存・再読み込み後に残る。
- 行位置がない旧フォームは従来の半幅を順に組み合わせ、全幅を別行にする。未知・重複・削除済みの項目や不正な行位置を許容し、新しく追加した項目は末尾へ補う。不正な3項目の同一行は分割して表示する。
- 配置の判定・全幅と2列の切替・キーボード移動にはAI作成画面と同じ `blueprint-layout.ts` を使用する。
- 既存の配色トークンを使用する。狭い作業領域ではパレットを上へ移し、640px未満ではカードを縦に並べる。共通サイドバー・カラー設定・AI設定は変更しない。

## フォーム配置対応時点の検証結果（統合ビルダー追加前）

- `npm run quality`: 成功。単体484件、32件スキップ。文字化け・ESLint・TypeScriptを確認し、既存の共通レイアウトのフォント警告1件のみ。
- 新規E2E2件: 成功。左右端の2列化、空き枠、連続Alt＋矢印、Esc取消、非表示と再配置、ファイル型、必須制約、補足、保存失敗時の保持と再試行、再読み込みを検証。
- フォームAPIで保存した順・幅・行位置を読み戻し、実行画面のCSSグリッドの行番号と比較。フィールドの順番・必須設定がフォーム変更で書き換わらないことも確認。
- モバイルE2Eは390px幅のChromiumタッチコンテキストで実際のCDPタッチ入力を送信。横はみ出しと保存後の再読み込みも確認。実機iPadは未検証。
- 全体E2E: 28件成功、失敗0、3件スキップ。アプリ作成・ワークフロー・スケジュール・5000件の既存性能検証を含む。初期化2件とworkflow-recoveryは専用の環境・明示的有効化を必要とするためスキップし、安全設定は変更していない。
- 本番Webpackビルド: 成功。隔離コピーを使用し、リポジトリの依存・ビルド設定・環境変数は変更しない。

自動検証は専用のローカルPostgreSQL DBで行い、作成したテストアプリは後処理で削除する。Supabaseやユーザーの既存データは自動検証の対象にしない。
