# 手動テーブル作成の統合ビルダー

2026-10-06。`/apps/[appId]/tables` の既定画面を、添付 `02-design-review-light.png` の構成に合わせて置き換えた。旧フォーム配置エディターだけの対応とは異なり、テーブル未作成・項目ゼロの状態からこの画面で設計できる。

## 画面と操作

- 上部: アプリ名、アプリコード、テーブル名、テーブルコード。新規テーブルのコードは自動生成・手動入力。既存コードは固定。
- 左: テキスト・長文・数値・日付・日時・真偽値・選択式の7部品。ドラッグで指定位置に新規項目を追加し、クリック／Enter／Spaceでも追加できる。登録済み項目を先に別画面で作る必要はない。
- 中央: 入力型別のフォームプレビュー。カードを上下に並べ替え、左右端へドロップして2列に配置できる。空の半幅スロットを保持。表表示では設計中の項目を一覧できる。
- 右: 表示名・コード・型・必須・選択肢・全幅／2列・入力補足・複製・削除／非表示。画面幅1280px未満では項目設定をドロワーにする。
- 保存内容: 項目数、行数、既存ビューの維持／一覧の自動作成、既存データの保護、下書き／公開済み状態を表示する。
- 下部: プレビュー／キャンセル、変更を戻す、一括保存。ガイドの案内ポップアップは保存ボタンに重ならない位置に表示する。
- ビュー、参照、一意制約、AIによる既存アプリの調整などは「詳細設定」に従来画面を残している。
- `/apps` はホームの「マイアプリ」へ転送する。パンくず・作成キャンセル・旧一覧URLから404にならず一覧へ戻れる。

既存のNavy・White・Darkのトークンだけを使い、グローバル配色を変更していない。AI生成用の10項目上限を既存テーブルに適用しない。

## 既存データを保護する規則

- 保存済みのフィールドコード・型は統合画面では固定。変更が必要な場合は既存の詳細設定・移行処理を使う。
- 未保存の項目は削除できる。保存済み項目の操作はフォームからの非表示であり、DBのフィールド・レコードを削除しない。テーブルの必須項目は、必須解除を明示しない限り非表示にできない。
- 既存12型はそのまま表示・配置できる。基本7型以外の新規作成・複製は詳細設定を使う。
- 一意制約、既定値、参照設定、計算設定、保存済みレコード、フィールドの定義順、編集対象以外のフォーム、既存ビューを保持する。
- 手動作成はサンプルレコードを追加しない。下書きは保存しても公開しない。公開済みアプリについては保存後の反映を画面で案内する。

## 保存API

`GET /api/apps/:appId/designer` はアプリ・テーブル・項目・フォーム・ビューとSHA-256リビジョンを返す。テナントとアプリ／テーブルの閲覧権限を確認する。

`PUT /api/apps/:appId/designer` はテーブル編集権限を確認し、アプリ名を変更する場合だけアプリ編集権限も必要。親アプリ行のロックとSerializableトランザクションで、テーブル・新規項目・既存項目の表示設定・フォーム・初期一覧ビュー・監査ログを一括保存する。途中の検証・DBエラーで全体をロールバックし、クライアントの設計を保持する。

再読込後のリビジョンが一致しない場合やDB競合では409を返し、上書きしない。再読み込み・フォーム切り替え・詳細設定への移動・変更取消では未保存設計の破棄確認を行う。`full` / `half` と `rowIndex` の保存・Runtime反映は既存の共通処理を使う。
